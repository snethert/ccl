# C/C4/B correctness execution

The new [runner](../../../tests/wasm/stage0/dynamic-call/README.md) implements the [dynamic-call protocol v0](../abi/dynamic-call.v0.md) for C, C4 and B through one corpus. Current execution is `DYNAMIC-CALL-r1`; its [summary](../evidence/dynamic-call-summary.json) and [index](../evidence/index.json) identify the complete pack. This new implementation has not received independent review or project acceptance.

Each candidate passes 53 positive cases and rejects 27 mutants/invalid configurations. The aggregate is 159 positive executions and 81 rejected controls. The runner freshly executes the existing boundary (12/9), integrated runtime (22/14/1,000 seeds) and logical-frame (11/11) prerequisites. It emits eighteen new records: S0-LL04-a/b and S0-LL13-a, plus the three candidate variants of S0-LL05-a/b/c/d and S0-LL21-b.

The corpus checks argument order through 32 arguments, closure self/environment, complete zero/one/six values, optional/rest/keyword binding, proper-list APPLY, nested calls with retained values, C callbacks and nonlocal restoration, typed slots/stubs, installation after moving GC, prebuilt redefinition and late Workers. Three 100,000-transfer chains per candidate alternate two and 32 arguments, checking bounded explicit stack/root use and live binding/cleanup extent. Ordinary invalid arity/designator/capacity paths use explicit fixture conditions. Wasm type traps are isolated rejection controls.

Every module and object, exact emitted WAT, schema/debug metadata, source snapshot, toolchain identity and case/control result is retained. Debug binding IDs and source sites are attached to exact code versions and emitted-WAT hashes. The loader checks installed binary identity, profile, imports, initialization and entry signatures. Matching engine types do not replace semantic role checks.

Two ordinary development failures changed the new fixture's result ownership. In r1, an active TCR result region was also exposed through a nonempty root record; a later collection attempted to relocate the same physical slot twice. The corrected protocol gives each result slot one scanner. In r2, nested output reuse left a stale per-frame count visible during inspection; reuse now resets the frame descriptor and TCR count together. Dedicated mutants reproduce both failures. Original development r1/r2 bytes remain retained; the earlier reviewed collector was not edited. A later control-development failure was an overly narrow rejection expectation: the code-version mutant was already rejected by the new source-metadata oracle before value comparison. Its original result is retained and the control now recognizes that precise earlier rejection.

The fixture is bounded: 32 arguments, six values, 512-byte activation, 16 KiB explicit stack per Worker, up to fifteen root records before a C helper, at most eight frames, sixteen immutable 8 KiB replies per Worker, and two 4 KiB semispaces in one fixed 1 MiB memory. Four ownership slots are reserved; at most three Workers are live. Larger cases require a revised fixture contract and new evidence. No arbitrary-size or production-scale claim follows from the tail test.

Function objects, keyword identities and symbol redefinition are hand-built surrogates. Policy 1 still materializes roots. Packaging uses separate callable modules and a support module; it is a correctness setup, not a production granularity decision. Neither generated CCL code nor browsers, cold image startup or ABI performance are covered.

The earlier seven accepted records remain separate and unchanged. The current aggregate selects those accepted records plus the eighteen new NOT_REVIEWED records, without inheriting acceptance into the new linked ABI kernel. The combined gate remains BLOCKED: 24 missing records and eighteen unreviewed records. D3 stays open. Next is independent review, then measurements under predeclared workload, granularity, startup and Worker assumptions. The native census and actual pass 2 remain separate work; H(G) has no scheduled obligation.
