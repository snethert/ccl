# B is the implementation ABI — 12 September 2026

Use B for the compiler implementation. All Lisp arguments use the explicit value stack; the Wasm entry takes `(self, nargs)` and returns `(value0, nvalues)`, with the existing owned region for extra values. This avoids splitting arguments between Wasm parameters and overflow stack slots. The user directed the project to stop spending effort ranking the roughly equal exploratory timings and choose on speed or simplicity. B is already the simplest candidate in the recorded design, so simplicity and clarity are sufficient grounds for this choice.

The reviewed C/C4/B corpus establishes B's correctness at its stated hand-built bounds. The exploratory results are consistent with B being competitive, but do not establish a speed advantage. The frozen benchmark policy's minima were never met: r2 had three trials per packaging, not the required thirty, and shorter warmup/sample durations. The project did not apply that rule to choose B. At the user's explicit direction, this is a dated project decision with an engineering rationale, not a benchmark outcome. Stage 1 may proceed on B without a measurement claim; its generated-code and remaining correctness obligations still apply.

Comparative timing, the proposed sensitivity controls and the extra comparison instrumentation are deferred. They do not block implementing B. Benchmark policy version 3 records this explicit change; the original version 2, failed/development runs and raw measurements remain retained. The 24 comparison rows remain unqualified, now an optional future worklist. S0-ABI-selection becomes a record of this engineering decision and its correctness basis, rather than a requirement to complete those timings. Its formal evidence record remains outstanding; this document is not a fabricated test execution.

C and C4 remain documented alternatives. Reopen the choice only if generated-code correctness or a representative workload exposes a concrete problem attributable to B, and a proposed alternative plausibly addresses it. If a performance comparison becomes necessary, validate sensitivity and use representative weights then. Do not build that comparison now.

The next work is the qualified census and a small pass-2 slice that emits B calls from actual U1 front-end output and compares results with native U1. Unsupported operations must fail explicitly. This ABI decision assigns no functional shared-compiler author. A separate 12 September exception in [CLAUDE.md](../../../CLAUDE.md) authorizes Codex's reversible native observation; [that harness has executed and its operator record is accepted](native-census.md). The [dependency extension](native-dependencies.md) and trace derivative await independent review; complete closure remains pending. Its disposable patched copies and images are evidence only. B implementation starts from pristine U1. Census results guide coverage, reachability and eventual workloads; missing weights no longer block the ABI choice.

Production module packaging remains a Stage 1 decision. Existing root/frame/cleanup, runtime ownership, generated-code confirmation and Stage 0 correctness obligations remain in force. Scale, startup, memory and browser evidence remain open product work, to be measured against useful generated code rather than used to prolong the hand-built ABI contest. H(G) remains optional future work.
