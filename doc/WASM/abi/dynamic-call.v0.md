# Dynamic-call correctness protocol v0

Status: C/C4/B hand-built experiment contract; no ABI selected. H(G) and specialized typed Lisp entries are optional future work.

The generic signatures are C `(self,nargs,a0,a1,a2)`, C4 `(self,nargs,a0,a1,a2,a3)` and B `(self,nargs)`, all returning `(value0,nvalues)`. Tagged values are wasm32 `i32`; counts are raw unsigned `i32`. Unused argument parameters contain fixture NIL (65). For candidate parameter count K, arguments K through N−1 occupy consecutive words at incoming VSP. Their reserved extent is `align16(max(N−K,0)*4)`. The caller owns that extent. The callee publishes its frame above it before any allocating, suspending or polling operation, and restores incoming VSP on return. The caller then releases overflow storage.

The fixture admits 0–32 arguments and 0–6 values. It reserves 16 KiB of explicit stack per Worker, 512 bytes per activation, at most eight logical frames, and at most fifteen published root records before entering a C helper (the unchanged collector admits sixteen including the helper). Overflow, generation exhaustion and malformed inputs fail explicitly. These are correctness bounds, not production capacity or measured resource budgets.

Each frame begins with the [64-byte logical debugger header](../contracts/debug-frames.md). The payload records stack/root/binding/handler/active-request checkpoints, a per-frame result descriptor, chunked argument roots (eight values per root record), six contiguous result roots and eight temporary roots. Self and each supplied argument have their own slot; all tagged values needed after a stopping boundary are reloaded. Raw addresses are rederived after movement. Debug policy is applied to reported availability; both policies still materialize roots in this fixture.

Before dispatch the caller supplies a rooted six-word output region via the TCR multiple-value descriptor. The callee computes in its own result region, copies the complete ordered sequence into that caller-owned region, restores checkpoints, and returns the pair. Zero values return NIL and zero. That region survives until its owner reuses or releases it. A caller retaining earlier results across another call copies them to its rooted temporary region first. Nested multiple-value-call and cleanup check every value, not only value0.

Every physical result slot has exactly one scanner. While the TCR descriptor owns a region, that region's linked root record has count zero; the TCR's count governs scanning. Switching the active region re-enables the prior region's six-word root record and disables the new region's record before publishing the new descriptor, without polling. Return, tail transfer, callback restoration and EH follow the same rule. Development r1 exposed duplicate scanning after a completed return and a later Worker installation; that original failed run is retained and a duplicate-ownership mutant must fail. Development r2 exposed a stale per-frame result count when its output region was reused; reuse now resets both the frame descriptor and TCR count before any stop, with its own retained mutant.

Tail transfer keeps the caller's output region and dynamic binding/handler extent. It caches required transfer values, removes the current frame without polling, rewrites the incoming overflow area for the new count, and uses an actual Wasm tail instruction. No GC or host entry is permitted between releasing those roots and publishing the successor frame. Long growing/shrinking chains poll while their frames are published and collect with live closure state. They must use bounded explicit stack and root storage. An enclosing cleanup frame retains its dynamic extent through the chain.

Every code version has a generic slot, ABI version, role and structural signature. Each uninstalled generic slot holds the matching shared stub. The stub publishes self/arguments and suspends on the reviewed C request protocol. Its bytes are available in the Worker's immutable cache before blocking; host completion identifies the requested module by digest. Installation rejects unauthorized initialization, wrong imports/profile/signature/role, missing bytes and digest mismatches before publishing entries. After collection the stub reloads roots, removes its temporary frame and tail-redispatches. Runtime adapters have explicit roles; matching Wasm signatures alone do not permit their substitution for Lisp entries. Old function objects retain their code/environment across prebuilt redefinition.

The corpus uses one definition for C/C4/B. Independent host expectations check argument order, unequal values, closure environments, optional/rest/keyword binding, proper-list APPLY and Lisp-condition paths for invalid calls. Wasm type traps are rejection controls, never the implementation of ordinary arity/designator errors. Cons fixtures and memory-ownership controls precede candidate execution. Final Wasm, C objects, source snapshots, metadata and quarantined mutants are retained.

Correctness packaging places the support module and callable modules in separate instances sharing one memory and table per Worker. This makes cross-instance indirect dispatch executable. It does not fix production module granularity. Selection measurements must predeclare their workload, granularity, warm/cold and Worker assumptions under the existing benchmark policy, after correctness and independent review.
