16.4.2  REPLAYING OUTPUT RECORDS

Replay and the output history

An output record holds the drawing operations that produced it, not the state that computed them. Replaying a record therefore reproduces its appearance without re-running the program that drew it, which is what allows a display to be repaired from its history alone.

A conforming implementation must ensure that replaying a record onto a stream is free of side effects on the record itself, so that the same record may be replayed onto several streams, in any order, with identical results.

The region argument restricts replay to the portion of the record that intersects it. Implementations are encouraged to use the record hierarchy to discard whole subtrees that lie outside the region before descending into them.

Where a record's position has been changed since it was created, replay uses the current position; the offsets supplied to the replay operation are applied on top of it.
