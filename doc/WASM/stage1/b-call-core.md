# Generated B call core — 16 September 2026

The required-argument call and multiple-value core is implemented in a
reviewed unit, accepted by the user and integrated byte for byte on
16 September 2026. The [integration record](integration-b-call-core.json)
binds the user decision, Claude’s sixty-fifth audit and the retained payload.
It does not execute either complete LL05 slot.

The real front end and pass 2 generate 34 functions. Eighty-eight native
cases cover 0–6, 16, 32 and 64 arguments/results, direct and indirect calls,
nested side effects, zero-value consumption, IF, PROG1 and
MULTIPLE-VALUE-PROG1. The target repeats them with low and above-2-GiB stacks,
with direct Wasm imports and with transparent observation wrappers: 352
comparisons. Twelve source refusals keep unsupported forms out; twelve
resource cases refuse insufficient stack/output space and misalignment.
Fifteen recompiled compiler mutants fail at their named first assertions.

Each invocation owns its arguments and result region. Retained results move
to explicit root records before another call reuses the output descriptor.
The physical scanner oracle checks ownership at 620 boundaries. Exceptions
restore VSP, root head and the result descriptor using exnref. The unchanged
LL07 primitive validator is now reached by the indirect-call adapter against
an owner-supplied table registry.

This is still a bounded runtime: no allocation, collector or polls; live
cons operands in Wasm locals need LL06/1D spill/reload qualification before
collection is enabled. Function handles are opaque fixture identities,
not production closures. Checked exception tags provide arity/designator/
capacity refusal boundaries, not the full Lisp condition path. Optional,
rest and keyword binding, APPLY, closure objects, lazy stubs, tails and
cleanup/binding extent remain required LL05 work.

Native R6/R6a passes with the accepted pristine 1A baseline reused: the new
registered suite passes 21,843 tests, the two registration changes remain
exactly explained, all 164 FASLs match after removal, and five architecture
tables/seventeen module profiles remain unchanged. The retained verifier
replays qualification, recompiles every positive/mutant compiler and compares
all generated bytes and outcomes. No new gate credit is claimed.

## Calling-convention subtraction — 28 September 2026

The [Phase 1 producer record](call-convention-results.md) removes redundant
normal callee restoration, dispatch/frame checks and argument initialization,
and moves immutable metadata checks to their producer. The public wrapper
retains full validation. The existing traced context slot at +44 caches the
tagged pool so moving collection updates it. Frame sizes, result budgets,
TCR publication and ABI version 1 remain unchanged.

[Phase 2](call-convention-phase2-rejected.md) was measured and rejected for
marginal call savings, no measurable READY gain and slower inline loops.
Its context-only delivery contract and runtime-adapter changes are absent.
Phase 1 is producer-verified and awaits independent review.
