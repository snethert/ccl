# Attempt 1 as reference: what the archived port established and what it got wrong

Status: reference, not evidence. The archived tree at `~/Source/ccl-attempt1` (branch `wasm-port`, 365 commits, 2026-02-01 to 2026-03-11, archive commit 0f082454) is read-only. Nothing from it is copied into this port; implementation starts from pristine U1. Every idea it suggests is re-derived and evidenced here before use. Its own documents were read as data, not as rules. This survey was made on 2026-09-13 by four read-only source surveys and is not itself verified beyond reading; attempt 1 never produced a native regression comparison for any of its shared-source edits, so none of its numbers carry R6 standing.

Fork point: attempt 1 forked from upstream master at ce99f8a7 (2025-04-14), 21 commits after v1.13. Its history was rewritten on 2026-02-08, so upstream SHAs are not ancestors; v1.13 appears as 5bfd5fc7 with an identical tree.

Current-design interpretation (Codex, 2026-09-13): the [bootstrap design review](../stage0/bootstrap-design-review.md) separates the survey's warnings from adopted requirements. In particular, the fixed memory gap, name-based class resolution and full-rebuild remedies described below are historical prescriptions, not current project rules. The shared-edit counts describe that attempt and do not predict U1's required changes.

## How far it got

The full pipeline ran: kernel and subprims linked, level-0 cross-loaded into a boot image, about 8,700 functions compiled into 1,110 boot and 7,557 runtime single-function modules, cold-boot-init completed, 41 level-1 FASLs installed in-process, an image saved (2.43 GB at its worst, about 3 MB after the const-pool fix), and `TOPLEVEL-LOOP` entered. It then crashed in `MAKE-HASH-TABLE`. No REPL ever ran and no Lisp-level test ever passed: 144 test functions compiled, 0 executed correctly. The last commit restored an "rc-72 baseline", meaning FASL loading was failing again at abandonment, with a multiple-value return-count collapse in `%FIND-SYMBOL` as the final unexplained blocker. No document in the tree records why it was abandoned.

## Design choices, outcome, and the current decision

| Concern | Attempt 1 | Outcome | Current design |
| --- | --- | --- | --- |
| Backend structure | No vinsns, no LAP. 209 acode handlers in `compiler/WASM/wasm2.lisp` emit binary directly through a private IR; one Wasm module per Lisp function, merged into batches by a Node script. | Compiled everything but left an unfixed loop-codegen bug near the 30-bit fixnum boundary, a `prog1` temp-local reuse bug and a heap-size overflow in `box_fixnum(untag)`. | Registered backend with vinsn templates through the existing seam (source-practicality review; ARM precedent 442 vinsns). |
| Code identity | Function object holds a boxed entry index into one shared `WebAssembly.Table`; constants delivered through per-entry const pools read via a host import. | Entry-index collisions between boot and runtime bundles caused mutual recursion (d9ac4470); stale indices after incremental rebuilds; const pools deep-copied class objects into every pool. | B: code id plus constants via self (D3). |
| Call ABI | Every call goes through kernel imports `wasm_funcall0..10`; args pushed on a TCR value stack; `car`, `svref`, `typecode` are host calls. | Worked but every Lisp operation was an import; 176M-funcall storms when an error path looped (f7b86bd2). | B: all arguments on the value stack, direct calls, subprims emitted. |
| Nonlocal exit | No Wasm exceptions. A `pending_throw` flag checked after every call site. | Loops that make no calls never saw the flag; a 50,000-step fuel counter was added as a guard, and that counter's storage was later zeroed by a memory collision. | Explicit traps and EH under D6; `try_table` restoration accepted in S0-LL13-c and S0-LL19-b. |
| GC | ARM `arm-gc.c` port, single-threaded mark-compact, no safepoints, allocation never triggers collection; GC invoked explicitly by the launcher between cold-load functions. | Compaction type-confusion (92bc3aa0); TCR allocation pointer stale after compaction. | D5 polling safepoints and owner-CAS admission, accepted in S0-LL20-a/b/c. |
| Layout | ARM-inherited constants and static base; image base equals the kernel's `__heap_base`. | Kernel bump allocator overran subprims data; function-table index collision with C function pointers; C heap grew into purespace; catch frames not dnode-aligned. | D1 x8632-derived layout with reserved ranges and rejection tests for range collisions. |
| Level-0 | Every ARM LAP function rewritten as plain Lisp in `level-0/WASM` (12 files, 362 defuns, 5,343 lines). | Hash functions had to bit-match the host's LAP; two mismatches (27 versus 29-bit masks) caused infinite probing. | Level-0 replacements are census nodes with implementation dispositions; hash and pname behaviour become explicit contract items. |
| Multiple values | `_mv` funcall variants with values in pseudo-registers plus the value stack. | Register convention wrong once (424c0c9e); terminal blocker was a return-count collapse. | B protocol covers six values in the accepted corpus; Stage 1 exit requires every multiple value under forced GC. |
| Tail calls | None; tail subprims were ordinary C calls. | Not exercised. | 100,000-step tail chains accepted in the dynamic-call corpus. |

## What it tells the Stage 0 census

**Seeds.** Attempt 1's required-at-start set, discovered by failure, is: `RESTORE-LISP-POINTERS` (its omission after image load was itself a recorded root cause), `TOPLEVEL-LOOP`, `TOPLEVEL`, `STARTUP-CCL`, `%TOPLEVEL-FUNCTION%`, the level-0 bootstrap error handlers `%KERNEL-RESTART`, `%ERR-DISP` and `%ERROR`, and `%SIMPLE-FASL-INIT-BUFFER` (dropped by an alias dedup, rc -72). This confirms proposed seeds 1, 6, 7 and 13 in `seeds.json` and suggests reviewing whether `%TOPLEVEL-FUNCTION%` and the level-0 error path need explicit seed entries rather than reachability through `RESTORE-LISP-POINTERS` and `ERROR`.

**Initialization cycle.** The error system is needed before any error can be signalled, but its level-1 definitions arrive by `$fasl-defun` over the level-0 bootstraps mid-load. Attempt 1 resolved this by defining the ten level-1 handlers under `/full` names and activating them with `fset` in `l1-boot-3` (ab98dc4d). That is exactly the "initialization cycle requires an explicit seed/phase split" case in the census contract. The closure must record this cycle and its schedule explicitly whatever mechanism Stage 1 chooses.

**Load order.** Attempt 1's 41-FASL startup list (`scripts/wasm/wasm-startup-order.lisp`) is the `level-1/level-1.lisp` `l1-load` order with one insertion (`l1-error-signal` after `l1-readloop`) and one tail (`dumplisp`); `level-1`, `version` and `l1-sockets` were excluded. The cold-load list is built LIFO by `$fasl-defun` and reversed to FIFO in `xfasload`, so level-0 functions drain before level-1; the first cold-load function is an `(in-package "CCL")` thunk. These are ordering witnesses to compare against the r7 observed order, not replacements for it.

**Conditional load the census must carry.** `level-1/l1-boot-2.lisp` loads `l1-error-signal` inside `(catch :toplevel ...)`. Without a file system it failed silently and left `%err-disp` unbound (2a2d23d3). The census contract's rule that absence of file opens never removes a required module is confirmed by this failure.

**Boot-image subprocess.** Attempt 1 gives no witness for it. Level-0 was cross-loaded in the host CCL and level-1 was installed in-process inside Node; the `--with-l1` variant that xloaded both into one image was disabled because it "regresses root-image startup". The obligation to witness the subprocess's L1 installation separately stands.

**Dynamic call sites.** The paths that actually bit at boot were: funcall of cold-load thunks, `$fasl-defun` installation, the `fset` activation above, the launcher's force-rebind pass (which destroyed keyword vectors, 37e14c4a), class references resolved through `FIND-CLASS` at build time, and SETF function names in `xload-resolve-function-name`. When bounding the 1,729 retained dynamic sites, these families deserve first attention.

**Operator slots.** Attempt 1 filled two empty operator-table slots and inserted three operators into `nxenv.lisp`, shifting the positional number of every later operator. The census pins evaluated operator slot IDs including reserved slots. Any Stage 1 operator addition must append, never insert, or the census identities break.

**Import and trap surface.** Attempt 1's kernel needed 18 host imports; each compiled function module declared about 65 generic imports; the subprims map had 132 entries generated from the ARM `sptab` order. That is a first draft of the import inventory the lowering/import/store classification needs, to be re-derived from the registered census backend rather than copied.

## What it tells Stage 1

**Shared-source cost, the best available R6 estimate.** Attempt 1 modified 79 pre-existing shared files, +6,587/-1,108 lines: compiler 5, lib 10, level-0 16, level-1 29, xdump 1, lisp-kernel 18. Forty-eight of them gained `wasm` reader conditionals, 384 lines. That is close to the reader-conditional density the source-practicality review flagged as understated cost. Eleven edits were unconditional and would each need their own before/after native evidence: `l1-clos-boot` (closure state to `defstatic` globals plus a bootstrap-phase macro), `l1-utils` (`proclaim` dispatch refactor), `lib/macros` (`def-ccl-pointers` and `def-load-pointers` rewritten with `nfunction`), `lib/db-io` (missing foreign functions become macros), `xdump/xfasload` (`let*` to `progv`, SETF name resolution, package cloning), `lib/nfcomp` (`fasl-dump-dispatch` clause reorder), `nx.lisp` (`*target-ftd*` binding), `nx1.lisp` (four float-to-fixnum handlers), `nxenv.lisp` (operator table), `l1-error-signal` (bounds check) and `lisptypes.h` (two static asserts). Several exist only because the backend could not compile closures or `progv` early; a backend that handles them removes the edits.

**Sizing.** Backend 9,610 lines with 209 handlers and no vinsns; level-0 replacement 5,343 lines; Wasm-specific kernel C 46,968 lines, of which the funcall/const-pool/image-fixup file alone is 8,842 and the C subprims provider 8,386. Compare the ARM precedent of about 30,000 lines total. Attempt 1's kernel was large because it reimplemented in C what the backend did not emit.

**Layout and linking rules learned.** Keep at least 1 MB between the kernel's `__heap_base` and any side module's data; `--table-base` above the C function-pointer range; check that the C heap cannot grow into purespace after image load; dnode-align every frame the GC walks. These become rejection tests under the Stage 0 "collide reserved memory or table ranges" mutant.

**Image rules learned.** Never deep-copy class or instance objects into per-code constant storage; resolve class references by name at build time. Run a GC before saving. Objects allocated by C `malloc` outside the Lisp heap are not serialized; anything the image must contain lives in the heap. Installing constants before cold boot can create non-canonical symbols; symbol identity must be established first. Incremental rebuilds that reuse entry indices corrupt the table; every rebuild is full.

**Compiler debts never root-caused.** Loop code generation near the 30-bit fixnum boundary, `prog1` temp-local reuse, `box_fixnum(untag(ptr))` overflow for heaps above 1 GB, `%pname-hash` width mismatch with the host, a single-float `*-2` recursion, and the terminal multiple-value count collapse. Each names a Stage 1 exit criterion: target-width arithmetic boundaries, argument and temporary preservation, canonical symbol and hash behaviour, and every multiple value.

**Process lessons the tree records about itself.** About 125 of the first 220 commits built a web UI before anything booted, and all of it was deferred. A 2,500-line "startup binding map" compensated for one missing call to `RESTORE-LISP-POINTERS` and was deleted once that was understood. Work proceeded "one blocker deep" with time-boxed investigations that produced workarounds, and a 40-minute compile cycle made trial-and-error the norm. Two AI-authored regressions were introduced in the launcher and kernel without understanding the invariants. The current rules on small commits, R6 before shared edits, retained failures and adversarial review answer each of these.

## Not to be carried forward

The pending-throw flag and fuel counter; per-function Wasm modules merged by script; entry-index code identity and const-pool tables; host-call implementations of primitive accessors; the ARM-inherited layout constants; explicit launcher-driven GC in place of safepoints; unconditional shared-source refactors that exist to avoid closures or `progv`; the level-0 pure-Lisp rewrites as a body of code (their inventory is useful, their text is not); any build or launcher script; any claim from its documents that has no execution record.
