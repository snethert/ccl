# Target loader

This runner starts a coordinated level-0 heap and code set, enters the original
`%toplevel-function%`, and loads the runtime through CCL's target `%fasload`.
Level-1 is compiled into bundles and is never host cross-loaded into this image.
The namespace supplies those bundles to the target opcode-72 handler and code
installer. Bootstrap hands off through `:toplevel` to `startup-ccl` in the initial
process, which handles ordinary `--load` arguments.

READY passes in two fresh Workers from the same level-0 image: 81 nested runtime
loads and two ordinary post-image `--load` files complete in each. The outer
`level-1` load hands off to the application through `:toplevel`, so it is counted
as an opened runtime bundle, not a normally returning LOAD. All 82 runtime
bundles compile without a stop. The traced run observes 5,028 distinct logical functions;
the second run disables the call/callback census but retains the LOAD observer.
The historical 21-file stop and failed corpus
at `ffbdb2e7` remain historical evidence.

The default build emits one archive per bootstrap tier and small FASL
containers: seven product engine modules, eleven instances at ordinary READY.
V1 remains available with `--v1` on the materialization scripts and is selected
for post-image fixtures. See the [consolidation report](../../../../doc/WASM/stage1/module-consolidation-results.md)
for byte equivalence, sizing, generations, ownership and engine checks.
`archive-check.mjs` and `archive-controls.mjs` check publication and refusals;
`archive-async-check.mjs` checks hashing suspension and caller mutation.
`retention-check.mjs` requires `node --expose-gc` and a RAM-disk output directory;
its heap snapshot is a separate diagnostic, never part of a timed READY run.
`archive-browser-check.mjs BOOT_WASM RUNTIME_WASM OUTPUT PLAYWRIGHT` checks
construction in installed Chromium, Firefox and WebKit versions. It uses
asynchronous browser instantiation to respect Chromium's main-thread size
restriction; it does not execute Lisp or qualify browser READY.

## Profile and implementation

Decision A2 requires host-backed stdout/stderr and startup in the initial
process. The interactive listener, in-image compiler, native scheduler, POSIX
networking, native debugger and interface database remain outside this profile.
The exact native-to-target load disposition is generated by `boot-order.py`.
MISC, TIME, PATHNAMES, COVER, LEAKS and CORE-FILES all load. Their native-only
operations are not thereby claimed to work: COVER's native LFUN readers and
LEAKS' native stack/reference scanners are excluded, and CORE-FILES contains no
Wasm-selected definitions under its existing Linux x86-64 conditional.
The native profiling API (`time`/`report-time`, `gctime`, `%page-fault-info`)
is also outside this profile; loading MISC does not provide those operations.
`join-process` reports that joining is unavailable in the single-Worker profile.

ASSQ uses CCL's own compiler macro. The allocator admits structure and istructure
node layouts; the collector scans packages. Callable VALUES supplements the
inline VALUES operator, including dynamic multiple-value delivery. Runtime
clock, calendar, directory and output requests use explicit host capabilities.
GC inhibition belongs to the collector owner and keeps address-hashed objects
stationary while native hash code retains indices. Its contract records the
first-lock relocation cost and refusal state.

The printer's BOGUS-THING-P checks actual owner areas without Lisp allocation or
collection; `%address-of` boxes the diagnostic word with the native fixnum
exception. The embedding allocates the advertised 1 MiB initial value stack.
No initializer failure is converted into success, and no missing runtime
function cell is filled by the boot harness.

Decision A3 rescinds the numerical replacement cap. `source-inventory.py` lists
reader branches and named Wasm primitives, including native antecedent candidates.
`execution-inventory.py` joins observed calls to installed code identities.
These are separate from unchanged-original execution credit; neither a matching
name nor a compiled or loaded module establishes that credit. Backend routes and
anonymous/generated bodies do not acquire original-body credit from this census.

## Validation

The single final evidence pack is
`ccl-evidence/2026-09-26-stage1-loader-completion-r1` beside the checkout. It retains
original failures, source/tool identities, qualification results and independent
Claude reviews. `checks/ready-r23/ready-r23.json` binds the two boot reports,
post-image compilation parent and both refusal runs to SHA-256 identities.
Its digest is `b979da0f9a6b411c306a2985b2478a23ddc0d13749cdd16c50f12529af08acca`.

The fresh final compiler corpus passes **26,204 comparisons with zero failures**.
Native qualification passes all 21,843 enabled tests (75 upstream-disabled),
all 164 FASL comparisons and every existing target profile. The reader matrix
passes 765 comparisons across 45 shared files and 17 profiles. Native-r8 binds
all 67 current proposal source hashes, including `l1-io`, `w32-prims` and the
backend; corpus-r5 includes the final primitive and fixture changes.

The user accepted the READY completion and subsequent consolidation, host and
SEP-1 changes after audit 188. That is the first commit-level review of READY;
the reviews cited in `ea82d8e7` and retained in the original pack were WIP
reviews of the uncommitted tree. The
[acceptance record](../../../../doc/WASM/stage1/acceptance-audit-188.json)
records the historical O-124/O-134 findings and the reviewer's corpus reuse
after ENOSPC. The [refusal follow-up](refusal-followup.md) verifies O-124's
existing class-mode fix and corrects O-134's generation-capacity boundary,
whose full corpus was independently replayed by audit 189: 26,204 fresh
comparisons, zero failures. O-124 and O-137 are closed. The
[audit 189 follow-up](load-error-followup.md) fixes the Lisp-facing refusal and
shared error context. Generation exhaustion runs in its own `refusals.lisp`
fixture; ordinary READY preserves the second generation.
The report field `level1CrossLoaded` is a declarative label, not independent
proof; the bound level-0 producer and actual target load events establish the
loading boundary. `firstFailure` can name a handled Lisp signal and must not
be read alone as a fatal boot failure. Corpus case IDs include serialized graph
identities; cross-build retention is checked by case names, multiplicities and
unchanged input producers rather than assuming those IDs stay identical.

The post-image file is compiled after a pinned boot image exists. Ordinary LOAD
must install its class, method and functions; assertions exercise CLOS, hash
tables, caught type errors, readers, pathnames, time, multiple values, startup
callbacks and nested GC locks. The file then prints its result and Unicode text
to both output streams. Separate A/B files mutate fresh instances to different
values and install different later functions. `ready-check.py` requires both
LOADs to return in both Workers. Required-bundle omission and an empty namespace
must stop without reaching the post-image marker.
The actual Lisp calls to the clock, timezone, CPU-time and directory adapters,
including read-only mutation refusals, are required observations in the traced
run. The two instances retain independent values 111/222 and later functions
returning 112/223.

`callbacks.py` binds the retained 35 native callbacks to their compiled FASL
bodies and reader events: 22 execute in target order and 13 have explicit profile
exclusions. The native order comparison includes nested REQUIRE loads, not only
the source file's top-level module list.

Native qualification compares all 164 FASLs, all existing target module profiles
and the native test corpus. Reader qualification covers 45 shared files across
17 profiles; unchanged foreign forms omitted from the reader harness remain
individually pinned. The compiler corpus keeps every per-case failure and writes
a failure record before refusing qualification. An injected-failure control
checks that reporting path independently.

Callable VALUES validates the complete list and result capacity before result
writes. Cyclic list refusal remains a raw checked 5, as in the existing APPLY
protocol; it is not claimed to be a catchable TYPE-ERROR. The rest-list allocation
is not claimed to match native VALUES performance.

The boot and bundle compiler select `*b-cpl-conditions*`, whose early error gate
preserves the original fatal code until the real class-based condition system
is installed. The retained non-class corpus runtime builds private condition
vectors without MAKE-CONDITION and can still invoke its fixture handlers in
mode 0; its older conditional gate is intentional and is not a READY path.
The focused early-error control covers the class runtime. Before class startup,
its lexical CAR handler receives a raw checked 5; ASSQ's compiler-macro CAR
uses the `type_error` tag. Neither is claimed to be a boot-time Lisp condition.

The selected condition corpus supplies a non-weak LFUN-NAMES table on the target
because that fixture has no cold-load phase and uses its qualified EQ table
representation. The native oracle runs the original fixture. The driver requires
exactly one CORE-CONDITION-PREPARE rewrite. This fixture setup is absent from the
real loader, which initializes the native-shaped table through level-0 code.

The invalid-word printer predicate is tested at the owner/service boundary;
the post-image Lisp printer exercises valid objects. Arbitrary corrupt-object
printing and transitive heap validation are not claimed by those observations.

## Reproduction

Use fresh output directories on the verified RAM disk. `--reuse` checks matching
WAT and five artifact hashes, and regenerates listings under the new module name.
`--compact` retains the bundle and records while removing transient per-module
materialization directories.

```sh
python3 tests/wasm/stage1/loader-target/build.py /private/tmp/ccl-work/loader-boot --boot0
python3 tests/wasm/stage1/loader-target/build.py /private/tmp/ccl-work/loader-bundles --level1 --compile-only
node tests/wasm/stage1/loader-target/bundles.mjs /private/tmp/ccl-work/loader-bundles --compact
python3 tests/wasm/stage1/loader-target/build.py /private/tmp/ccl-work/loader-postimage --postimage=/private/tmp/ccl-work/loader-boot
node tests/wasm/stage1/loader-target/boot0.mjs /private/tmp/ccl-work/loader-boot /private/tmp/ccl-work/loader-boot/runtime-binaries --bundles=/private/tmp/ccl-work/loader-bundles --bundles=/private/tmp/ccl-work/loader-postimage --startup-load=/ccl/bin/loader-postimage.w32fsl --startup-load=/ccl/bin/loader-instance-a.w32fsl --expect-ready
python3 tests/wasm/stage1/loader-level1/qualify.py native /private/tmp/ccl-work/loader-native
python3 tests/wasm/stage1/loader-level1/qualify.py readers /private/tmp/ccl-work/loader-readers
python3 tests/wasm/stage1/loader-level1/qualify.py corpus /private/tmp/ccl-work/loader-corpus
```

Use `--trace` for a complete dynamic call census. `--trace-from=PATH` activates
observation only when that bundle opens and is diagnostic partial coverage.
`--inspect-code=ID` instruments implicit checks in one generated module. Observed
runs retain the original and observed identities and are distinct from the
run without the call census. `--expect-ready` makes a stopped Worker fail the
runner's exit status.

## Startup baseline (module consolidation P-0)

`startup-baseline.py` runs one fresh Node process on retained boot and bundle
artifacts. It verifies RAM-backed work and cache mounts, limits the run to
600 seconds, kills the process group on timeout, and writes `timing.json` even
when READY is not reached. It does not rebuild Lisp or add collections.

```sh
python3 tests/wasm/stage1/loader-target/startup-baseline.py /private/tmp/ccl-work/p0 /private/tmp/ccl-work/boot-r21 /private/tmp/ccl-work/bundles-r18 --timeout=600
```

The output directory must be new. `inputs.json` pins the command, engine,
instrumentation sources and input manifests; the normal loader authenticates
the bundles and boot artifacts. `ready.json` is the unchanged boot result
format. `events.main.jsonl` and `events.worker.jsonl` retain raw timestamps,
completed spans, per-file accounting and memory milestones. `run.json` records
the Node child's exit status, timeout and macOS `wait4` peak RSS. Retain these
files on persistent storage when finalizing evidence.

The optional `boot0.mjs --timing=PREFIX` switch enables those journals.
Default startup wraps only the boot functions consumed by the READY report;
`--trace` still wraps every boot function and newly installed function. Timing
rows are buffered in batches of 256 and flushed at checkpoints, memory samples
and finish; a killed Worker can lose up to 255 pending rows.
Admission, bundle decoding, compilation/materialization, root-cell allocation,
publication and actual collector copies have separate timers. The host install
span includes record decoding and installer bookkeeping outside the nested
root/publication spans. Per-file accounting follows the innermost open file;
admission and namespace decoding identify their requested file explicitly.
Inclusive spans contain their child spans; `exclusiveMs` removes that overlap.
Main-thread time overlaps Worker time and must not be added to it.

`worker:lisp.run` in the exclusive breakdown means time outside the measured
services. It includes Lisp execution, unmeasured numeric/allocation fast paths,
the existing boot observer and measurement overhead. This is an instrumented
baseline, not a claim of pure Lisp CPU time. The Worker construction and
send-to-start interval include structured cloning and thread startup.

Memory counters are bytes. RSS is process-wide; each thread's other Node
counters cover that thread. `arrayBuffers` is already included in `external`.
Neither these counters nor linear-memory extents are additive RSS components
([Node memoryUsage documentation](https://nodejs.org/api/process.html#processmemoryusage)).
`allocatedHeapBytes` includes objects allocated since the last collection;
`lastCollection.liveHeapBytes` records live movable Lisp data at that earlier
timestamp. Static/image objects are additional. Collector `storage` gives
current heap spaces, scratch and root areas, whose extents describe allocated
address ranges rather than resident pages. No forced collection changes the
workload at READY.

The [startup execution result](../../../../doc/WASM/stage1/startup-execution-results.md)
records the SEP-1 changes, measurements, sample decisions and verification.
For a compiler change, `archive-equivalence.mjs KIND SOURCE ARCHIVE - OUTPUT`
assembles each fresh unlinked compiler module as its own comparison baseline.
For packaging-only changes, pass the retained v1 directory in place of `-`.
`startup-helpers-check.mjs BEFORE_BOOT AFTER_BOOT OUTPUT` compares the emitted
hot helpers, including checked refusal and memory preservation. The general
compiler corpus explicitly regenerates its test-only collection hook from the
current generated leaf. The lower-level preparation helper retains its
fixed-parent hash gate when regeneration is not requested, but the current
qualification driver always requests regeneration and does not exercise that
gate (audit 188 O-140).
