# Generated rest lists and APPLY

This reversible compiler proposal adds `&rest`, including optional/rest/key
combinations, and APPLY through real front-end spread-call IR. The reviewed
binding corpus remains part of the test. No complete LL05 slot is claimed.
The main checkout stays at the accepted binding unit until review.

Rest cells are genuine D1 conses in the owned allocation area named by the
production TCR. The emitter checks alignment, bounds and the whole required
extent before writing, initializes CDR/CAR pairs, advances the allocation
pointer, then publishes the bound root. No call or safepoint occurs during
construction. Allocation survives a later exception: escaped cells remain
valid. Empty rest lists allocate nothing. This is an exhaustion-checked bump
allocator, not the collector or its slow path.

APPLY evaluates the designator, fixed operands and final list exactly once
in source order, keeping their values in a root record. Tag and memory
checks, cycle detection and a capacity bound validate the list. A runtime-
sized argument frame is filled before checked table dispatch. The
existing result transfer and exceptional restoration rules are preserved.

The old 64-argument ceiling is removed. Incoming extents and allocation
sizes are calculated in i64 before narrowing, and runtime storage determines
capacity. The corpus executes calls through 1,024 arguments and 129 required
parameters, including long keyword lists. The source reader's existing
budget remains a compiler-input bound. The separate 64-value result limit
remains explicit work for complete LL05 qualification.

Independent Python, native CCL and Wasm oracles compare every result and the
reachable heap graph, preserving original identities and naming newly
allocated cells by discovery. Tests use both low and above-2-GiB stacks and
allocation areas, direct imports and observation wrappers. The target also
checks allocation counts, untouched heap tails, physical root ownership,
stack fences, exhaustion, count overflow, malformed pointers and circular
lists. Circular lists are target-only controls; they are not sent to native
APPLY. All compiler mutants are recompiled through the real front end.

Function designators and keywords remain fixture-owned identities; no
production closure/symbol objects or full condition system are supplied.
Root inspection does not establish moving-GC spill/reload behavior. No
lazy installation, tail transfer or collection claim follows from this unit.

removal build. The verifier requalifies R6/R6a, recompiles every positive and
mutant compiler, compares generated bytes and reruns the oracles. One pack
retains new evidence and original failures, referencing unchanged inputs.
